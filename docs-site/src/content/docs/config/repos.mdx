`files:` renders one file from one template. A neovim configuration is a
directory with a hundred files and its own history, and templating it would be
absurd. It wants cloning.

```yaml
repos:
  - url: https://github.com/you/nvim-config
    dest: ~/.config/nvim
    ref: main          # optional -- a branch or tag
    only: linux        # optional, like everywhere else
```

## One directory out of a repository

`subdir:` takes a single directory and puts **its contents** at `dest`. A neovim
config that lives in `nvim/` of a dotfiles repo lands as `~/.config/nvim`, not
`~/.config/nvim/nvim`.

```yaml
repos:
  - url: https://github.com/you/dotfiles
    dest: ~/.config/nvim
    ref: main
    subdir: nvim
```

The clone itself lives in bedouin's store. `dest` holds a **snapshot bedouin
owns**, which is the trade: a file you create inside `dest` is not in the
repository, so the next `sync` removes it. Put things you edit in the repo.

A `subdir:` that does not exist at that ref is refused before `dest` is
touched, so a typo costs you nothing.

<Aside type="note" title="subdir needs tar">
The export runs `git archive | tar -x`, so the machine needs `tar` as well as
`git`. Most have it; openSUSE Leap's base image does not, and git does not pull
one in. `bedouin ssh` and `bedouin cloudinit` install it. Elsewhere bedouin
tells you to, rather than failing halfway through.
</Aside>

## What apply does

| State | Action |
|---|---|
| Not there | `git clone --depth 1 [--branch ref]` |
| There, and bedouin cloned it | **nothing** |
| There, and bedouin did *not* | **adopted — never touched** |
| Dropped from the config | the clone is deleted, if bedouin made it |
| `url:` changed | the old clone comes out, the new one goes in |

<Aside type="caution" title="Your directory stays yours">
A `dest` that already exists and is not in bedouin's state is **adopted**: it
is recorded and never written to. Your hand-managed nvim config is not
bedouin's to clobber.
</Aside>

## Present is done

A repo bedouin cloned is a no-op on later runs, the same rule as
[`version: latest`](/bedouin/config/packages/). Pulling on every apply would
make `plan` claim a change it cannot know about without going to the network,
and it would never converge.

**`bedouin sync` is what pulls** — the config repository and every declared
repo, with `--ff-only`. What happens to your commits is your call, so a pull
that cannot fast-forward is reported and the rest continue. A `subdir:` snapshot
is re-exported, which is how a moved branch or a re-pointed tag arrives.

One repo failing does not stop the others, but `sync` **exits non-zero** if any
of them did not end up as declared. Scripts and `bedouin ssh` read that.

## Bounds

`dest` must be under `$HOME`. No submodule recursion.

Private repositories work through the git setup you already have. If the GitHub
CLI is on `PATH`, bedouin adds `gh auth git-credential` to the helpers git
already consults — added, not substituted, so your own helper keeps working.
Git is never allowed to prompt: a repo bedouin cannot read is an error with a
sentence, not a clone that hangs until the step times out.

## Coexisting with chezmoi or stow

This is the seam. Move one directory at a time: point a `repos:` entry at it,
let bedouin adopt what is already there, and delete it from the other tool when
you are ready. Nothing has to happen at once.
